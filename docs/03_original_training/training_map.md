# Original training code — map

Draft, 2026-10-23, for wiring the models to a new trainer. Paths are in `_remote_data/yao/` unless marked "ours".

## Two versions of the code

yao is a git repo. The committed state (HEAD, 2025-12-01) is the paper-era code; the working tree was edited later (up to June 2026).

| | committed (paper era) | working tree (2026) |
|---|---|---|
| trainer | `main.py`, self-contained (dataset, losses, loop) | `main.py` imports from `src/`; crashes, because `get_dataset` is commented out in `src/datasets.py` |
| model code | `moduler.py` (the module name inside the paper checkpoints) | `src/models.py` (defines `SEBlock` twice) |
| generator | `generator_realtime.py` + `moduler_gen.py`: 36 bands over 350–1000 nm, σ = 0.01, satellites only (`index < 10000`) | same files, `src/` copy of the simulator: 350–2000 nm, σ = 0.2, slots 0–299 / 300–599 / 600–999 = satellites / shapes / patches (30/30/40) |
| data dirs | `satellite_project/database/<type>/` (pool), `.../data/<type>/` (fixed set) | `data_yes_id/database/...`, `data_yes_id/data/...` |

Read the committed files read-only with `git show HEAD:main.py`, `HEAD:generator_realtime.py`, `HEAD:moduler.py`.

## Data flow

- `generator_realtime.py --run_forever False` writes slots 0–999 to the pool and the same samples to the fixed set; `--run_forever True` then overwrites random pool slots forever (all CPU cores) while training reads the pool.
- Per slot, three files: `mask/{i}.npy` [15, 15] (label), `blur_cube/{i}.npy` [36, 15, 15] (model input), `spectral_cube/{i}.npy` (clean cube, unused by the classifier).
- `<type>` = `Pristine` is only a folder name.
- We dont have to follow the same pipeline with saving files, the synthetic data can be generated by some dataloader workers in the new code.

## `main.py` training loop

- Dataset `get_dataset`: raw `blur_cube` as float, `mask` as long; `safe_load_numpy` retries because files are overwritten mid-read; no normalization, no augmentation.
- The file list is built once (1000 paths); an epoch is one pass over the pool, whose contents change during the pass.
- `SpectralSpatialHSIModel(36, 47)`, `nn.CrossEntropyLoss()` (unweighted, all pixels, background included), Adam lr 1e-3, weight decay 1e-6, batch 30, shuffled.
- `StepLR(10, 0.5)` is created but `scheduler.step()` is commented out, so the learning rate stays constant.
- No validation. Training stops after 200 epochs without a new minimum training loss; each new minimum overwrites `resluts_n_model/model.pt` (TorchScript via `torch.jit.trace`).

## Evaluation behind the paper tables

`notebook/testing.ipynb`: loads both `resluts_n_model/yes_id` checkpoints (cell 10); test set `data_yes_id/data/Pristine/` (the fixed 1000 samples), batch 1 (cell 7). Materials: sklearn per-class report over all pixels, background included (cells 35, 39). Shape: binary nonzero accuracy and F1 per sample, ± std across samples (cells 46–58).

## 2026 trainers (may have something useful)

`train_yes_id_3dcnn_proto_srr.py` (the cleanest), `train_yes_id_srr.py`, `train_yes_id_proto_srr.py`, `train_yes_id_srr_norm.py`:

- argparse + a `TrainConfig` dataclass; train on the live pool, validate on 200 fixed samples from `data_yes_id/data/<type>`.
- Per epoch: pixel accuracy, mean IoU, macro F1, binary nonzero metrics, written to `metrics.csv`; settings in `config.json`.
- `last_ckpt.pt` and `best_ckpt.pt` (by validation mIoU), each `{"model", "optimizer", "epoch", "metrics"}`.
- Options: per-sample normalization, class-balanced CE, self-supervised augmentations (noise, spectral dropout, ±1 px shift).
- Our baseline weights come from `resluts_n_model/3dcnn/Pristine_basic_3dcnn_seed33` (300 epochs, batch 32, Adam 1e-3).
- `submit.sh` (SLURM) runs the generator and then this trainer, but the forever-generator call never returns, so the two must have run as separate jobs.

## Pitfalls when reusing

- The fixed set is the samples that first filled the pool, so validation overlaps training at the start.
- Three separate files per slot, overwritten concurrently: a cube and its mask can come from different scenes.
- Stopping and checkpointing in `main.py` use training loss only.
